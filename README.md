# UF Depot

Инженерная платформа по ультрафильтрации: узел непосредственной коагуляции перед УФ и модуль UF Calc (промышленная УФ-система N+X).

## Версия 0.2 — что работает

| Раздел | Что делает |
| --- | --- |
| `/coagulation` | Справочник товарных коагулянтов (неограниченно на каждый тип; добавить / изменить / копия / удалить; «по умолчанию») и справочник методик расчёта дозы (выражение или таблица по качеству воды и данным продукта, с единицами, областью применимости, основанием и рабочим диапазоном pH; «по умолчанию»). Без входа справочники хранятся в браузере, после входа — в аккаунте. Доза по методике из качества исходной воды, решение о необходимости коррекции pH. 5 коагулянтов, паспорт с обязательной базой концентрации, заданная доза, пересчёт баз (металл / Al₂O₃ / соль / кристаллогидрат / товарный), расходы при Qmin/Qном/Qmax, два режима расхода («только коагуляция» и «с установками УФ»), теоретический баланс щёлочности, коррекция pH (ручная доза или титрационная кривая), FeSO₄ с независимым статусом окисления, контактные камеры, трубопровод, требуемые характеристики насосов-дозаторов, протокол расчёта |
| `/uf` | Событийное годовое моделирование N установок: фильтрация → FF → BW, CEB по общему циклу, группы BW-станций, очередь и продление, баланс ОО с возвратом; режимы «найти Qnet» и «найти J» (обратный решатель с повторной проверкой) |
| `/login`, `/calculations` | Вход только через Telegram (Login Widget, подпись проверяется на сервере); «Мои расчёты» — неизменяемые снимки входов и результатов |
| Встроенные методики дозы | СНиП 2.04.02-84*, п. 6.16 (табл. 16, ф. 6, Св по п. 6.65; отменённый документ — справочно), РД 153-34.1-37.502-2000, п. 7.4 (0,07·ПО мг-экв/л, проверка по п. 6.5, pH по п. 6.4), справочные Rodriguez et al. 2000 и ЗХР 2020; рекомендация по типу объекта (ВОС / ТЭС); цитаты пунктов, пометка о сверке формул. Тексты документов — `docs/normative/` |
| `/methods` | Реестр методик: опубликована только ручная доза; методики, требующие источников |
| `/api/health` | Проверка состояния |
| `/api/auth/telegram`, `/api/auth/logout`, `/api/me`, `/api/catalog`, `/api/calculations` | Вход, справочник пользователя (версии методик неизменяемы), сохранённые расчёты; доступ только владельца |
| `POST /api/coagulation/calculate`, `POST /api/uf/calculate` | Расчётные API (детерминированное ядро, без LLM) |

Не входит в v0.2: проекты и версии, документы (ТКП, схема, DOCX/PDF/Excel), EN/ZH, редактор стадий и методик. Значения по умолчанию — демонстрационные.

## Структура

```
src/core/units         единицы и стехиометрия
src/core/coagulation   профили коагулянтов, пересчёты, расчёт, методики, безопасный парсер выражений
src/core/uf            балансы, шаблоны режимов, событийное ядро, обратный решатель
src/app                страницы и API (Next.js App Router)
src/server             БД, сессии (только сервер)
scripts/migrate.mjs    миграции схемы
tests                  Vitest: §24.1 A–D и функциональные проверки
docs                   описание проекта, исходные ТЗ, HTML-прототипы
```

## Запуск

```bash
npm install
npm test          # тесты ядра
npm run dev       # http://localhost:3000
npm run build && npm start
```

## Развёртывание

Railway, сервис из этого репозитория (`railway.json`): сборка `npm run test && npm run build`, старт `npm start` (порт из `PORT`), проверка `/api/health`. Перед стартом выполняются миграции (`scripts/migrate.mjs`). Переменные (см. `.env.example`):

- `DATABASE_URL` — PostgreSQL (на Railway: `${{Postgres.DATABASE_URL}}`);
- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather (секрет; задаётся только в переменных сервиса);
- `TELEGRAM_BOT_USERNAME` — имя бота без @.

В @BotFather: `/setdomain` → домен сайта. Без этих переменных расчёты работают, вход отключён.
